utils/ — Package Overview
=========================

This package is a modular Python client for the Poli-Millionaire quiz game API.
It lets students programmatically log in, browse competitions, play games, and
check leaderboards without writing raw HTTP calls themselves.

------------------------------------------------------------------------------
__init__.py
    Package entry point. Imports and re-exports every public class and exception
    so users can do `from utils import MillionaireClient` (or any other symbol)
    without knowing which sub-module it lives in.

base.py
    Low-level HTTP layer (BaseClient). Wraps the `requests` library to handle
    session cookies, authentication state, URL construction, and HTTP error
    mapping. All other modules call this one instead of touching `requests`
    directly. Raises typed exceptions based on the HTTP status code returned by
    the server.

client.py
    Top-level facade (MillionaireClient). Combines BaseClient with all four
    feature modules (auth, game, competitions, leaderboard) into a single object.
    This is the class students instantiate. Also provides the convenience method
    `play_game(competition_id, answer_strategy)` that runs a full game loop with
    a user-supplied answering function.

auth.py
    Authentication module (AuthModule). Wraps the login, logout, and "who am I?"
    API endpoints. Stores the session cookie inside BaseClient so subsequent
    requests are automatically authenticated.

game.py
    Game module split into two classes:
    - GameModule  : starts a new session or fetches state for an existing one.
    - GameSession : a stateful wrapper around a running game. Exposes properties
      (current_question, earned_amount, time_remaining, …) and the answer() /
      answer_by_text() methods students call to submit answers. Keeps local state
      in sync with the server after each answer.

competitions.py
    Competitions module (CompetitionsModule). Lists all available competitions,
    retrieves the full prize pyramid / config for a specific competition, and
    provides a helper to find a competition by name.

leaderboard.py
    Leaderboard module (LeaderboardModule). Fetches the ranked list of players
    for a given competition. Helpers: get_top(n) for the top-N entries and
    find_player(username) to locate a specific player's position.

models.py
    Data classes (pure Python dataclasses + one Enum). No network logic here —
    only structured representations of API responses.
    Key types:
      - User             : logged-in account info (id, username, role)
      - Competition      : competition metadata (id, name, levels, …)
      - CompetitionConfig: competition + full prize pyramid
      - Question / Option: a quiz question and its answer choices
      - GameState        : snapshot of a game session (status, level, deadline, …)
      - AnswerResult     : outcome of submitting one answer
      - MoneyLevel       : one rung of the prize pyramid
      - LeaderboardEntry : one row of a leaderboard
      - Leaderboard      : full leaderboard (competition + list of entries)
      - GameStatus (Enum): in_progress | completed | failed | timeout

exceptions.py
    Exception hierarchy rooted at MillionaireError. Every error carries the
    HTTP status code and raw response body for easier debugging.
    Subclasses:
      - AuthenticationError : 401 / not logged in
      - ValidationError     : 400 bad request
      - NotFoundError       : 404
      - RateLimitError      : 429
      - ServerError         : 5xx
      - GameError           : game-logic violations (e.g. answering with no question)
      - TimeoutError        : question deadline expired
